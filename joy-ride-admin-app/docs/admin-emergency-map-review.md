# Admin emergency tracking map — Step 25

Opening an emergency detail shows a red car at its saved incident point and a separate blue/grey car at the selected Driver's latest reported fleet GPS. No coordinate interpolation, artificial offsets, route assumptions or automatic movement of the map view are introduced. Buttons centre on either point; overlapping coordinates are explicitly labelled. A ride-linked vehicle plate is identified as ride-linked; active registrations do not prove which vehicle was at the incident.

Incident source is GPS, MANUAL_PIN or unknown for legacy data. A manual point is fixed and has no measured GPS accuracy. Labels show capture/selection time, age and reported accuracy. Missing/invalid coordinates never become a default vehicle position. GPS reports older than 60 seconds, future/uncertain timestamps, offline/unknown online flags and failed refreshes are treated conservatively. Accuracy circles are drawn only for known GPS measurements with a bounded native radius. Broad accuracy is explained in text. Markers are reported estimates, not verified physical presence or a promise of rescue.

The existing Admin-authenticated /driver-locations/fleet endpoint is requested with cancellation, timeout and safe error handling. Only the incident Driver's row is retained; both driverId and nested Driver identity must match. Unrelated/private fields are stripped. Polling runs every 15 seconds while the detail screen is focused and the app active, stops when resolved, and pauses if alert status cannot be refreshed. GPS errors do not disable acknowledgement/resolution. Old GPS is explicitly labelled after a failed refresh. Existing safe Cache-Control header handling is preserved.

Native Google Maps uses the already declared react-native-maps 1.20.1 and vector icons. Web provides a coordinate-based fallback. Existing fleet map, API/EAS/signing configuration, dependencies, authentication, inbox, review and audit actions are preserved. No new Maps keys or permissions are introduced.

The authoring fixture passed 24 offline safety/map contracts and changed-code lint; it does not have the Maps SDK or vector-icons package. The installer therefore runs full TypeScript and strict lint against the actual installed dependencies on the laptop, followed by the offline checks. Rendering, car markers, centre controls, map loading failure, stale/offline GPS, foreground/background behaviour, changing GPS without moving the incident, and the existing response workflow still require verified APK phone tests.

Keep all PRs Draft. This preparation does not migrate a database, deploy, publish or build an APK. Update only the isolated test backend/database after destination and CI checks before integrated tests. Production remains unchanged.
